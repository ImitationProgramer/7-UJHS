# Goal 7 — 음성으로 출발지와 도착지 설정

길찾기 화면에서 음성 입력을 시작하고 “왕십리역에서 서울숲으로 갈 거야”처럼 말한다. OpenAI Realtime이 한국어 대화를 처리하고 TMAP 장소 검색 도구를 호출한다. 검색된 이름·주소를 확인하면 기존 출발지/도착지 필드와 지도에 반영한다. 이후 기존 길찾기 버튼으로 시설 기준 경로 비교를 실행한다.

## 로컬 설정

`services/api/.env`에 다음 항목을 추가한다. 기존 TMAP 키는 유지한다.

```dotenv
OPENAI_API_KEY=사용자의_키
# 필요할 때만 모델을 지정한다.
# OPENAI_REALTIME_MODEL=gpt-realtime-2.1
```

환경 파일을 변경한 뒤 API 서버를 다시 시작한다. 키는 서버에서만 읽으며 VITE 환경 변수나 브라우저 저장소에 넣지 않는다. 브라우저 마이크는 localhost 또는 HTTPS에서 사용할 수 있다. HTTP LAN 주소에서는 마이크가 제한될 수 있다.

## 연결과 도구

- `GET /api/navigation/voice/status`: 설정 유무만 반환한다.
- `POST /api/navigation/validate-location`: 브라우저가 받은 현재 좌표를 기존 서버의 성동구 행정 경계로 검사한다. 외부 TMAP 호출 없이 범위 여부만 반환하며, 범위 밖 좌표는 출발지에 적용하지 않는다.
- `POST /api/navigation/voice/session`: 브라우저의 SDP offer를 받아 서버 설정과 함께 OpenAI `/v1/realtime/calls`에 전달하고 SDP answer를 반환한다. 허용된 Origin만 세션을 만들 수 있다.
- 음성과 모델 응답은 WebRTC로 전달한다. 데이터 채널에서 대화 자막과 함수 호출을 처리한다.
- `search_places({query,target})`: 기존 TMAP 검색 API를 호출한다. 성동구 내 후보만 선택에 사용한다.
- `select_place({place_id,target})`: 해당 입력의 최신 검색 후보 ID를 검증한 뒤 기존 장소 선택 경로로 전달한다. 모델이 임의의 좌표를 설정할 수 없다.
- `end_session({})`: 명확한 음성 대화 종료 요청에 마이크·WebRTC·오디오 리소스를 정리한다. 장소 취소나 이동 정지와 구분한다.

장소 확인은 음성으로 완료한다. 후보가 여러 개면 검색 결과 번호·이름·구분되는 주소를 최대 3개씩 읽고, 사용자가 말한 번호·이름으로 최신 후보를 선택한다. 단일 후보도 이름·주소를 읽고 말로 확인받는다. 구분 근거가 없으면 추가 단서를 요청한다. 후보·주소는 기본적으로 접힌 **장소 상세 보기**에 읽기 전용으로 제공하며 화면 선택을 요구하지 않는다. 지도·경로·센서 표시는 유지한다.

장소를 바꾸면 기존 경로 결과와 Replay 미리보기가 초기화된다. 음성 기능은 경로 점수, 횡단 시설 판정, Replay 분류에 개입하지 않는다.

## 사용 범위와 데이터

시작 버튼을 누른 뒤 마이크를 사용하며 화면에서 종료할 수 있다. 연결 종료·오류·화면 이탈 시 오디오 트랙과 WebRTC 연결을 정리한다. 대화는 최대 15분으로 제한한다. 인식한 말과 AI의 응답은 화면에 표시하며 서비스 코드가 음성 파일이나 대화 기록을 디스크·DB에 저장하지 않는다. 음성 처리를 위해 OpenAI로 전송되는 사실을 화면에 표시한다. 제공자의 데이터 처리 정책은 별도 적용된다.

이번 범위는 현재 위치를 이용한 출발지·도착지 설정과 공개 Replay 경로 재검토의 음성 설명이다. 실시간 GPS 추적, 카메라, 음성 건강 판단은 포함하지 않는다.

## 현재 위치 기본값과 이동 중 설명

### 성동구 밖 행사장의 시연 모드

`services/api/.env`에 `NAV_DEMO_MODE=1`을 설정하고 API를 재시작한 뒤 화면을 새로고침하면 **왕십리역 (시연 위치)**을 기본 출발지로 사용한다(WGS84 37.56120587, 127.03701584). 이 모드에서는 브라우저 실제 위치나 위치 권한을 요청하지 않는다. 음성 시작 후 목적지만 말하면 되고, 다른 출발지를 말하면 검색을 통해 바꿀 수 있다. 화면과 AI 첫 안내에서 가상 시연 출발지임을 알린다. 장소 상세는 접힌 상태와 지도를 유지한다.

현재 로컬 `.env`에는 사용자 요청으로 시연 모드를 켰다. 일반 위치 사용으로 돌아가려면 `NAV_DEMO_MODE=0`으로 바꾸거나 항목을 제거하고 API 재시작·화면 새로고침을 한다. 키는 변경하지 않는다. 가상 출발지에도 기존 행정 경계 검증과 실제 TMAP 경로 조회·시설 추천 정책을 적용하며, 휴대폰 센서/GPS 스트림은 변경하지 않는다.

검증: 백엔드 62개·단위 55개·브라우저 29개 통과, 로컬 Replay 자료 의존 9개 건너뜀. 실제 OpenAI의 ‘시연은 왕십리역에서 시작해요’ 응답과 브라우저 실제 위치 요청 0회를 확인했다. 왕십리역→서울숲 실제 조회는 HTTP 200·후보 4개이며 기존 시설 정책상 추천 없음이다. 출발지를 바로 바꿀 때 발생하던 Leaflet 종료 후 줌 콜백 오류도 자동 줌 전환 비활성화로 방지하고 브라우저 오류 0개를 확인했다.

### 일반 위치 모드

음성 시작 시 출발지가 비어 있으면 브라우저 위치 권한을 요청한다. 위치를 얻으면 현재 위치를 출발지로 사용하며, 별도 출발지 표현이 없는 장소명은 목적지로 해석한다. 이미 지정한 출발지는 유지한다. 권한 거부·시간 초과·위치 정확도 100m 초과 시 위치를 만들어 넣지 않고 직접 출발지를 선택하도록 안내한다. 정확도 기준은 제품의 임시 입력 품질 기준이며 안전 보장이 아니다. 기존 성동구 서비스 영역 검증은 서버에서 유지한다.

음성 세션은 최대 15분 유지하며 수동 종료도 가능하다. 공개 Replay 재생 중 유효 행동 분류가 나오면 최초 1회, 이후 기록 시간 15초 간격 또는 행동 변화 시(최소 5초 간격) 가상 현재 위치에서 목적지까지 TMAP 후보를 재조회한다. 목적지 20m 이내에서는 중복 조회를 생략한다. 일시정지·연결 끊김·경로 변경 시 진행 중 조회를 취소한다.

새 결과는 별도 ‘동행 중 경로 다시 살피기’ 영역에 표시하고, 연결된 Realtime에는 현재 행동과 재조회 결과를 전달하여 읽게 한다. 기존 미리보기 경로를 유지하므로 Replay 좌표 대응이 도중에 바뀌지 않는다. 공개 Replay는 실제 안내견의 GPS 기록이 아니며 이 기능으로 위험도·선호도·건강을 추론하거나 시설 가중치를 변경하지 않는다. 실제 센서/GPS에 의한 자동 경로 전환은 아직 구현 범위 밖이다.

추가 검증: 현재 위치/음성 도구 단위 테스트 포함 총42개, 백엔드57개 통과. 실제 OpenAI 연결에서 가상 위치를 출발지로 사용한 뒤 “도착지만 말씀해 주세요”라는 응답을 확인했다. 사용자 실제 위치·마이크는 이 검증에 사용하지 않았다. 실제 Dog45 모델 재생과 모의 TMAP 응답을 조합해 가상 현재 위치 재조회, 원래 경로 유지, 일시정지·출발지 변경 후 늦은 응답 무효화를 확인했다.

## 음성 후보 선택 개선 검증 — 2026-10-09

현재 위치 범위·경로 결과 전달 수정: 현재 위치는 서버 경계 확인 후 출발지로 반영하며, 범위 밖이면 원인을 말하고 성동구 안의 출발지를 요청한다. 최초 조회의 성공·추천 없음·실패·25초 시간 초과를 음성에 전달한다. 사용자 발화/도구 처리 중에는 최신 결과를 보류했다가 응답 종료 뒤 한 번 전달하고, 장소 변경 후 늦은 결과는 폐기한다. 오류 뒤 같은 목적지 재확인도 재조회한다. 현재 위치를 임의로 성동구 좌표로 바꾸거나 서비스 범위를 확대하지 않는다.

이 수정 후 백엔드 58개·단위 54개·브라우저 28개 통과, Replay 자료가 필요한 9개 건너뜀. 실제 OpenAI 연결에서 가상 성동구 밖 위치의 출발지 재질문과, 실제 TMAP 경로 조회 후 추천 경로 없음 안내가 한 번 전달되는 것을 확인했다. 실제 사용자 위치/음성 대신 가상 위치·데이터 채널 테스트 문장을 사용했다.

- 백엔드 음성·경로 57개, 프런트엔드 단위 51개, 전체 브라우저 23개 통과. 로컬 Replay 모델·자료가 필요한 브라우저 9개는 건너뛰었다.
