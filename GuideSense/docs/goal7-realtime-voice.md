# Goal 7 — 음성으로 출발지와 도착지 설정

길찾기 화면에서 음성 입력을 시작하고 “왕십리역에서 서울숲으로 갈 거야”처럼 말한다. OpenAI Realtime이 한국어 대화를 처리하고 TMAP 장소 검색 도구를 호출한다. 검색된 이름·주소를 확인하면 기존 출발지/도착지 필드와 지도에 반영한다. 이후 기존 길찾기 버튼으로 시설 기준 경로 비교를 실행한다.

## 로컬 설정

`services/api/.env`에 다음 항목을 추가한다. 기존 TMAP 키는 유지한다.

```dotenv
OPENAI_API_KEY=사용자의_키
# 필요할 때만 모델을 지정한다.
# OPENAI_REALTIME_MODEL=gpt-realtime-2.1
```

환경 파일을 변경한 뒤 API 서버를 다시 시작한다. 키는 서버에서만 읽으며 VITE 환경 변수나 브라우저 저장소에 넣지 않는다. 브라우저 마이크는 localhost 또는 HTTPS에서 사용할 수 있다. HTTP LAN 주소에서는 마이크가 제한될 수 있다.

## 연결과 도구

- `GET /api/navigation/voice/status`: 설정 유무만 반환한다.
- `POST /api/navigation/voice/session`: 브라우저의 SDP offer를 받아 서버 설정과 함께 OpenAI `/v1/realtime/calls`에 전달하고 SDP answer를 반환한다. 허용된 Origin만 세션을 만들 수 있다.
- 음성과 모델 응답은 WebRTC로 전달한다. 데이터 채널에서 대화 자막과 함수 호출을 처리한다.
- `search_places({query,target})`: 기존 TMAP 검색 API를 호출한다. 성동구 내 후보만 선택에 사용한다.
- `select_place({place_id,target})`: 해당 입력의 최신 검색 후보 ID를 검증한 뒤 기존 장소 선택 경로로 전달한다. 모델이 임의의 좌표를 설정할 수 없다.

장소를 바꾸면 기존 경로 결과와 Replay 미리보기가 초기화된다. 음성 기능은 경로 점수, 횡단 시설 판정, Replay 분류에 개입하지 않는다.

## 사용 범위와 데이터

시작 버튼을 누른 뒤 마이크를 사용하며 화면에서 종료할 수 있다. 연결 종료·오류·화면 이탈 시 오디오 트랙과 WebRTC 연결을 정리한다. 대화는 최대 15분으로 제한한다. 인식한 말과 AI의 응답은 화면에 표시하며 서비스 코드가 음성 파일이나 대화 기록을 디스크·DB에 저장하지 않는다. 음성 처리를 위해 OpenAI로 전송되는 사실을 화면에 표시한다. 제공자의 데이터 처리 정책은 별도 적용된다.

이번 범위는 현재 위치를 이용한 출발지·도착지 설정과 공개 Replay 경로 재검토의 음성 설명이다. 실시간 GPS 추적, 카메라, 음성 건강 판단은 포함하지 않는다.

- 브라우저: 길찾기 4개 + 음성 3개, 총 7개 통과. 모의 WebRTC 도구 호출로 두 입력란 설정, 임의 ID 거부, 대화 표시, 종료 시 마이크/연결 해제, 권한 거부 시 수동 검색, 키 미설정 시 마이크 미요청을 확인했다.
- 활성 음성 UI 320px에서 가로 넘침 없음, axe 위반 0개. 워크스페이스 타입 검사·프로덕션 빌드·diff 공백 검사 통과.
- 실제 localhost 화면에서 음성 입력 영역과 키 미설정 안내를 확인했다. 이후 사용자 키를 반영해 서버를 재시작하고 실제 OpenAI 세션 생성(HTTP 200, SDP answer), WebRTC 응답 전사 도착, 정상 종료를 확인했다. 검증에는 가상 마이크를 사용했으며 사용자 음성을 녹음하지 않았다. 실제 한국어 발화 인식과 장소 선택 대화는 사용자 마이크로 확인해야 한다.

## 현재 위치 기본값과 이동 중 설명

음성 시작 시 출발지가 비어 있으면 브라우저 위치 권한을 요청한다. 위치를 얻으면 현재 위치를 출발지로 사용하며, 별도 출발지 표현이 없는 장소명은 목적지로 해석한다. 이미 지정한 출발지는 유지한다. 권한 거부·시간 초과·위치 정확도 100m 초과 시 위치를 만들어 넣지 않고 직접 출발지를 선택하도록 안내한다. 정확도 기준은 제품의 임시 입력 품질 기준이며 안전 보장이 아니다. 기존 성동구 서비스 영역 검증은 서버에서 유지한다.

음성 세션은 최대 15분 유지하며 수동 종료도 가능하다. 공개 Replay 재생 중 유효 행동 분류가 나오면 최초 1회, 이후 기록 시간 15초 간격 또는 행동 변화 시(최소 5초 간격) 가상 현재 위치에서 목적지까지 TMAP 후보를 재조회한다. 목적지 20m 이내에서는 중복 조회를 생략한다. 일시정지·연결 끊김·경로 변경 시 진행 중 조회를 취소한다.

새 결과는 별도 ‘동행 중 경로 다시 살피기’ 영역에 표시하고, 연결된 Realtime에는 현재 행동과 재조회 결과를 전달하여 읽게 한다. 기존 미리보기 경로를 유지하므로 Replay 좌표 대응이 도중에 바뀌지 않는다. 공개 Replay는 실제 안내견의 GPS 기록이 아니며 이 기능으로 위험도·선호도·건강을 추론하거나 시설 가중치를 변경하지 않는다. 실제 센서/GPS에 의한 자동 경로 전환은 아직 구현 범위 밖이다.
